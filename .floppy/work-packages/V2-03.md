## 4. Frozen project_id semantics

`project_id` is a random UUIDv4 in lowercase canonical hyphenated representation, created exactly once when protected accepted state is formally established and immutable thereafter.

For new projects it is created with the accepted onboarding operation that first establishes `.floppy/accepted-state.json`. For adopted non-Floppy projects it is created when formal adoption and project-origin acceptance are recorded. Older Floppy projects predating V2-03 do not receive a fabricated or reconstructed ID merely because a new model or conversation opens the project.

It must not be derived from project name, repository URL, filesystem path, Git commit, Git branch, administrator identity, AI provider, conversation identifier, accepted scope, or accepted project outcome. Repository moves/renames, continuity-preserving forks, orchestrator/model replacement, and lawful project revisions do not change it.

## 5. Frozen protected_state_sha256 semantics

The digest covers only the parsed `protected_state` JSON object and excludes the complete accepted-state file and the digest field itself.

Canonical bytes are exactly equivalent to:

```python
json.dumps(protected_state, ensure_ascii=False, sort_keys=True, separators=(",", ":"), allow_nan=False).encode("utf-8")
```

The stored value is lowercase hexadecimal SHA-256 of those bytes. Rules: recursively deterministic key ordering; no insignificant whitespace; UTF-8; no BOM; no trailing newline in hashed bytes; direct Unicode serialization; JSON native number/boolean/null types preserved; NaN and Infinity invalid; checkout CRLF/LF outside parsed string values cannot affect the digest; characters inside JSON strings are not silently normalized.

## 6. Frozen accepted-state presence rules

Before activation, no activation registration plus no `.floppy/accepted-state.json` is valid legacy/pre-acceptance state.

After activation: ACTIVE plus missing record fails; record present plus activation registration absent fails; ACTIVE plus record present requires schema, project ID, canonical hash, binding, revision-history, and authority-isolation validation.

Older already-accepted Floppy projects that never adopted V2-03 may legitimately lack the record. The validator must never fabricate a record or project ID. After committed activation, later removal of the registration or record is continuity removal/drift and cannot be reinterpreted as legacy absence.

## 7. Accepted revision model

ORIGINAL is immutable. Administrator-accepted project-level revisions append to history. CURRENT_ACCEPTED is deterministic. Prior accepted revisions remain SUPERSEDED_BUT_HISTORICAL. Ordinary operational change cannot silently mutate protected state.

At minimum, deterministic failures distinguish `ACCEPTED_STATE_HISTORY_REWRITE` from `ACCEPTED_STATE_SILENT_DRIFT`. Detection is structure/digest/checkpoint based and does not require model judgment.
