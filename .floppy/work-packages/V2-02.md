## 2. Purpose

V2-02 defines the provider-independent user entrance and adoption route into Floppy.

The intended first-use path is:

`find Floppy -> copy one canonical prompt -> open an AI conversation -> describe the project naturally -> determine the actual session capability route -> enter Route A, B, or C -> complete project onboarding/adoption as required -> reach the paired Continuity Overseer / initial Project Orchestrator handoff`

User onboarding remains distinct from project onboarding / Floppy 1E.

## 3. R1 paired-bootstrap handoff

At new-project acceptance into Floppy-controlled operation, or at formal adoption of an existing non-Floppy project into Floppy, V2-02 must expose the user-facing handoff into the paired bootstrap required by R1.

The handoff must require:

1. a Continuity Overseer prompt; and
2. an initial Project Orchestrator / Floppy Z prompt.

They must be issued together, remain separate conversations, and be bound to the same accepted project origin.

The shared accepted project origin must include at minimum:

- project identity;
- original intended observable project outcome;
- accepted project scope;
- accepted exclusions;
- major project constraints;
- verified starting state;
- accepted project plan and roadmap;
- exact repository checkpoint where applicable;
- current authority state;
- Continuity Overseer identity; and
- initial Project Orchestrator identity.

V2-02 defines the trigger and handoff only. It does not implement V2-04 runtime behavior.
